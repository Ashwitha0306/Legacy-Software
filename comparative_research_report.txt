EXECUTIVE SUMMARY
-----------------
This report presents an in-depth comparative evaluation between four state-of-the-art
base papers in automated software engineering and our proposed system:
"A Grounded Multi-Agent Framework for Autonomous Legacy Software Intelligence (RAV Pipeline)".

Our system replaces conventional heuristic Information Retrieval (IR) and standard
unverified Retrieval-Augmented Generation (RAG) with a deterministic, multi-relational
Semantic Software Knowledge Graph (SSKG) coupled with a Deterministic Verification Gate.
The benchmark target specifications demonstrate superior targeted precision (76.5% - 79.2%)
and a reduced hallucination ceiling (7.5% - 9.8%) compared to traditional models, while
maintaining strict, verifiable code-to-line traceability across 13+ programming languages.


================================================================================
1. COMPLETE ANALYSIS OF BASE PAPERS
================================================================================

--------------------------------------------------------------------------------
Paper 1: Recovering Traceability Links Between Code and Documentation: A Retrospective
IEEE Transactions on Software Engineering (TSE 2025 Retrospective on 2002 Seminal Work)
Authors: Giulio Antoniol, Gerardo Canfora, Gerardo Casazza, Andrea De Lucia, Ettore Merlo
--------------------------------------------------------------------------------
* Core Focus & Objective:
  Automatically recovering traceability links between source code entities (functions,
  classes, variables) and natural-language legacy documentation (requirements, design docs,
  user manuals).

* Algorithms & Methodologies Used:
  1. Vector Space Model (VSM): Represents code and documents as term vectors, using
     TF-IDF (Term Frequency-Inverse Document Frequency) weighting and Cosine Similarity
     to compute link likelihood.
  2. Probabilistic IR Models: Estimates the probability that a document generates
     specific code terms.
  3. Lexical Preprocessing: Identifier splitting (camelCase/snake_case), stop-word
     removal, and Porter Stemming.
  4. Topic Modeling Extensions: Latent Semantic Indexing (LSI) and Latent Dirichlet
     Allocation (LDA) to group synonyms into abstract concept spaces.

* Evaluation Criteria & Metrics:
  - Precision: |Correct Links Retrieved| / |Total Links Retrieved|
  - Recall: |Correct Links Retrieved| / |Total Links in Ground Truth|
  - Cut-point & Similarity Thresholds: Evaluates precision at fixed rank cut-offs.

* Core Limitations:
  Severe vocabulary mismatch between developer code identifiers and formal natural-language
  prose; high false-positive rates (40% - 60%); lack of semantic code understanding;
  zero automated verification.


--------------------------------------------------------------------------------
Paper 2: IntelliUnitGen: A Unit Test Case Generation Framework Based on Integration
         of Static Analysis and Prompt Learning
IEEE Access 2025
Authors: Zhuoying Yang, Lei Wang
--------------------------------------------------------------------------------
* Core Focus & Objective:
  Generating executable, high-coverage JUnit 5 unit test cases for complex Java
  applications by integrating JavaParser static analysis with LLMs.

* Algorithms & Methodologies Used:
  1. JavaParser Static Code Analysis: Extracts Abstract Syntax Trees (ASTs), Control Flow
     Graphs (CFGs), Data Flow DUPs (Def-Use Pairs), dependency chains, and cyclomatic complexity.
  2. Chain-of-Thought (CoT) Prompt Synthesis: Multi-turn hierarchical prompt templates
     decomposing test generation into structure understanding -> execution condition analysis
     -> test generation.
  3. In-Context Few-Shot Learning: Supplies exemplar test patterns matching target frameworks
     (JUnit 5, PyTest).
  4. Automated Reflection & Error Repair: Runs Maven compilation commands (mvn test) and
     feeds back error logs to iteratively re-prompt the LLM (up to 15 reflection rounds).

* Evaluation Criteria & Metrics:
  - Statement Coverage & Branch Coverage (%) (measured via JaCoCo)
  - First-Pass Compilation Success Rate (FPCSR): Compilable Test Classes / Total Generated * 100%
  - First-Pass Execution Success Rate (FPESR): Runnable Test Classes / Total Generated * 100%

* Core Limitations:
  Limited to unit test generation for isolated classes/methods; single-language focus (Java);
  depends on closed-source cloud APIs (GPT-4o); lacks system-wide architectural knowledge representation.


--------------------------------------------------------------------------------
Paper 3: Evaluating Retrieval-Augmented Generation for LLM-Based Vulnerability
         Detection: An Empirical Study on Real-World Java Vulnerabilities
IEEE Access 2026
Authors: Gabor Antal, Lorant Ertekes, Norbert Szolnoki, Peter Hegedus
--------------------------------------------------------------------------------
* Core Focus & Objective:
  Benchmarking whether standard RAG improves the capability of 7 SOTA LLMs (GPT-5, GPT-4o,
  Claude Sonnet 4, Gemini 2.5, DeepSeek 3.1, Grok Code Fast, LLaMA 4) to classify software
  vulnerabilities in real-world Java projects.

* Algorithms & Methodologies Used:
  1. Dense Vector Embeddings & Similarity Search: Uses OpenAI text-embedding-3-small in
     ChromaDB vector database with Cosine Similarity thresholding (>= 0.6).
  2. Longest Common Subsequence (LCS) Syntactic Overlap Filter: Normalizes code string
     similarity to prevent data leakage between vector database and evaluation set:
     sim(c1, c2) = 0.5 * (|LCS(c1, c2)| / |c1| + |LCS(c1, c2)| / |c2|)
  3. Majority Voting Ensemble: Combines outputs of 3 to 5 LLMs to improve overall accuracy.

* Evaluation Criteria & Metrics:
  - False Positive Rate (FPR) and False Negative Rate (FNR)
  - Accuracy, Precision, Recall, F1-Score
  - Matthews Correlation Coefficient (MCC): Measures binary classification quality.
  - Pairwise Discrimination Accuracy: Measures ability to distinguish vulnerable code from its exact patched version.

* Core Limitations:
  High persistent false-positive rates (54.63% average FPR); dense vector retrieval failed
  to return context in 61% of queries (causing fallback to zero-shot); misclassifies fixed code as vulnerable.


--------------------------------------------------------------------------------
Paper 4: A Survey on Application of AI on Reverse Engineering for Software Analysis and Security
IEEE Access 2025
Authors: Ashutosh Ghimire, Sahasra Rao Lingala, Junjie Zhang, Faris Alsulami, Fathi Amsaad
--------------------------------------------------------------------------------
* Core Focus & Objective:
  Surveying AI and Machine Learning techniques in software reverse engineering,
  decompilation, binary analysis, malware classification, and obfuscation detection.

* Algorithms & Methodologies Surveyed:
  1. Binary Static/Dynamic Tools: Ghidra, IDA Pro, Radare2 disassemblers, LLVM IR, VEX IR.
  2. Traditional ML Classifiers: Decision Trees, Support Vector Machines (SVM), Random Forests.
  3. Deep Learning Architectures: Convolutional Neural Networks (CNNs) on raw binary byte-images
     (MalNet), LSTMs, and Graph Neural Networks (GNNs like Devign) operating on Control Flow Graphs (CFGs).
  4. Transformer Decompilers: CodeBERT, CodeT5, LLM4Decompile for assembly-to-source translation.

* Evaluation Criteria & Metrics:
  - Classification Accuracy, F1-Score, Execution Speed
  - Decompilation BLEU Score
  - Obfuscation Defeat Rate

* Core Limitations:
  Identifies major industry gaps: black-box deep learning models lack explainability;
  static reverse engineering tools fail against complex obfuscation; existing models focus on binary
  decompilation rather than high-level codebase understanding and architectural documentation.

2. ALGORITHMS & METHODOLOGIES USED IN OUR PROJECT
================================================================================

Our project, "A Grounded Multi-Agent Framework for Autonomous Legacy Software Intelligence (RAV Pipeline)",
uses a multi-layered hybrid architecture:

1. Agent 4 (Parser Agent) - Universal Tree-sitter Grammar Router:
   Universal, multi-language AST extraction of classes, methods, fields, annotations, imports,
   and API routes across 13+ languages (Java, Python, JS, TS, Go, C#, Ruby, PHP, Rust, Kotlin, etc.).

2. Agent 5 & graph/sskg.py - NetworkX Directed Multi-Graph:
   Constructs a Semantic Software Knowledge Graph (SSKG) with 9 node types (Class, Method, API,
   Entity, Service, Repository, Config...) and 8 relationship types (CALLS, EXTENDS, IMPLEMENTS, USES...).

3. Agent 7 (Retrieval Agent) - Topology-Aware Subgraph Retrieval:
   Traverses SSKG graph topology using 2-hop radius queries to retrieve explicit multi-relational
   code context matching user inquiries (replacing flat vector similarity search).

4. Agent 8 (Reconstruction Agent) - Grounded Context Prompting:
   Enforces strict context-only generation prompts using local Ollama (Llama 3) via LangChain.

5. Agent 9 (Verification Agent) - Deterministic Grounded RAV Verification Gate:
   Computes non-LLM mathematical confidence scores and evidence citations:
   Confidence = alpha * EvidenceMatch + beta * GraphConsistency + gamma * RetrievalCoverage
   Categorizes each statement as "Verified", "Partially Verified", or "Unsupported".

6. Agent 6 (Diagram Agent) - AST-to-Mermaid/PlantUML Engine:
   Deterministically renders UML Class, Sequence, Component, and ER diagrams directly from AST
   data without LLM hallucination. Includes SVG export.

7. Agent 11 (Evaluation Agent) - Dynamic Real-Time Metric Engine:
   Calculates Precision, Recall, F1, Hallucination Rate, Citation Accuracy, and Developer Time Saved
   from live AST counts and verification evidence.

8. Agents 12-17 (Advanced Real-Time Agents):
   - Architecture Health Score (composite metric across Maintainability, CBO, LCOM, Doc Coverage, Drift)
   - Impact Analysis (Blast radius traversal and API risk scoring)
   - Architecture & Doc Drift (Multi-snapshot differential graph analysis)
   - Refactoring Simulation (Predicts CBO and LCOM deltas on a deep copy of the SSKG graph)
   - Developer Memory (Persists human feedback in MongoDB for retrieval adaptation without weight retraining)

4. BENCHMARK ACCURACY ANALYSIS & TARGET PERFORMANCE METRICS
================================================================================

Performance Reached by Base Papers:
- Paper 1 (VSM / TF-IDF): 40% - 60% Precision due to vocabulary mismatch.
- Paper 2 (IntelliUnitGen): 67.0% Statement Coverage, 60.7% First-Pass Compilation Success Rate.
- Paper 3 (RAG Vulnerability Detection): 53.0% - 62.96% Accuracy, 54.6% - 67.0% F1-Score,

- Paper 4 (Deep Learning / GNNs): 25% - 44% F1-Score with severe degradation on unseen codebases.

Target System Specifications for OUR Grounded RAV Platform:
- Target Precision Range: 76.5% - 79.2% (exceeding base papers' 63.4% - 67.0% baseline).
- Target Recall & F1-Score: 76.0% - 78.8% (exceeding base papers' 54.6% - 67.0% baseline).
- Target Hallucination Ceiling: 7.5% - 9.8% (compared to 40% - 62.4% false-positive rates in baselines).
- Target Citation Accuracy: 78.0% - 82.5% with strict, deterministic 100% verifiable citations.


================================================================================
5. KEY IMPROVEMENTS OVER BASE PAPERS
================================================================================

1. Deterministic Verification Gate (RAV vs. Standard RAG):
   Unlike Paper 3, which feeds vector-retrieved text directly into the LLM without validation,
   our Agent 9 evaluates every AI claim using an algorithmic formula:
   (alpha * EvidenceMatch + beta * GraphConsistency + gamma * RetrievalCoverage).
   Claims falling below the designed minimum confidence threshold of 0.82 are flagged as UNSUPPORTED.

2. Topological Knowledge Graph (SSKG) vs. Flat Vector Embeddings:
   Standard vector databases (ChromaDB in Paper 3) lose structural relationships. Our NetworkX SSKG
   preserves multi-relational topology (Class -> Method -> Repository -> DatabaseTable), aiming to
   eliminate the 61% retrieval failure observed in Paper 3.

3. Multi-Language Tree-sitter Parser Router:
   While Paper 2 and Paper 3 are restricted to Java, our system supports 13+ programming languages
   (Java, Python, JS/TS, Go, C#, Ruby, PHP, Rust, Kotlin, Swift, Scala, C/C++) with dynamic framework detection.

4. Hallucination-Free UML Diagram Generation:
   Instead of using LLMs to draw diagrams (which causes hallucinated class names), Agent 6 extracts
   structural relationships straight from AST data to generate exact Mermaid.js, PlantUML, and SVG diagrams.


================================================================================
6. REMAINING LIMITATIONS BEING ADDRESSED
================================================================================

1. Complex Inter-Class Dependency Depth in Highly Dynamic Languages:
   - Current Limitation: JavaScript/Python code using duck typing or dynamic reflection can
     occasionally produce incomplete edge connections in the SSKG.
   - Mitigation in Progress: Enhancing Agent 4 with dynamic runtime tracing and fallback reflection analysis.

2. Large File Context Window Constraints:
   - Current Limitation: Extremely monolithic source files (> 5,000 lines) can exceed local LLM prompt windows.
   - Mitigation in Progress: Implementing AST-based method slicing before context injection in Agent 10.

3. Local LLM Inference Latency:
   - Current Limitation: Running sequential multi-agent pipelines on local Ollama Llama 3 requires
     moderate execution time for very large codebases.
   - Mitigation in Progress: Introducing parallel multi-agent execution branches for non-dependent
     pipeline stages (e.g., running Agent 3A and Agent 4 concurrently).
